# post-eval-report-builder

用 AI 把一个投资项目的散乱资料生成一份符合评估机构固定范式的《投后评价报告》Word 文档。

这是一个 Claude Code skill（技能包）。资产评估机构反复给不同项目出投后评价报告——骨架和话术是固定的、内容随项目变。本工具把固定的部分（章节结构、免责话术、格式排版、打分表）沉淀成模板和规范，让 AI 读资料、填能确定的事实、按范式生成文字，把需要专业判断的地方留空并给出提示，最后渲染成 Word 交给评估师复核定稿。

---

## 它解决什么问题

评估机构做投后评价报告有个固有痛点：每一单的报告结构、免责声明、打分表框架、排版规格几乎一模一样，真正随项目变的只是"这个项目叫什么、投了多少钱、经营/建设得怎么样"。人工从头排一份几十页的 Word、逐字誊固定话术、反复对格式，既慢又容易出错。

本工具的做法是把这份工作切成四层，各自交给最合适的角色：

- **固定不变的部分**（章节骨架、免责话术、字体字号、打分表框架）→ 沉淀进模板和 reference 规范，一次做好反复用。
- **能从资料里确定的事实**（项目名、各项金额、日期、主体名称、财务数据、政策文号）→ AI 读资料填进去。
- **需要专业判断的部分**（风险定档、成功度打分、评价结论）→ AI 不碰，留空并附上对应话术提示，交给持证评估师。
- **排版渲染** → 代码只灌数据、不动样式，保真度等于那份真实模板本身。

## 两类范式

工具按项目性质分两套范式，第一步先判断做哪一类：

| | 股权类 | 工程类 |
|---|---|---|
| 评什么 | 对一家企业的股权投资（长期股权投资、被投公司经营） | 一个工程建设项目本身（市政/建筑/改造/环保整治的概算、招投标、施工、造价、质量、验收、运营） |
| 章节骨架 | 四章制：项目基本情况 / 投资过程评价 / 投资效益评价 / 投后评价结论 | 七章制：项目概况 / 后评价工作情况 / 实施全过程总结与评价 / 效果效益评价 / 环境和社会效益评价 / 目标和可持续评价 / 结论与经验教训 |
| 编号体系 | 中文层级「一、（一）1、（1）」 | 阿拉伯多级「1 / 1.1 / 1.1.1」 |
| 正文字体 | 宋体 | 仿宋_GB2312 |
| 免责声明 | 独立成页，法律免责逐字固定 | 无独立声明章节，靠正文资料来源限定语替代免责功能 |
| 成功度打分 | 多维度成功度表（四档评级） | 三种模型选一：工程细表（新建工程适用）/ 多维度成功度表 / 专家团加权指标 |

判断口诀：评的是「对一家公司投了钱、看它经营得怎么样」= 股权类；评的是「盖了/改了一个工程、看这工程建得怎么样、钱花得对不对」= 工程类。拿不准就看资料里有没有招投标 / 施工合同 / 竣工验收 / 工程结算——有这些就是工程类。

工具还能出两种产物层级：几十页的**完整版报告**（从原始资料生成），和 10 页量级的**后评价专项报告**（从一份已完成的完整版报告浓缩、供报送上级）。二者与股权/工程范式正交，先定产物层级再定范式。

## 核心原则

1. **AI 只填确定项，专业判断留空。** 风险定档、成功度打分、评价结论这类需要专业资质和主观判断的内容，一律留空并附话术提示，绝不替评估师编分数、编结论。
2. **免责声明和固定话术逐字不改。** 法律和规范措辞原样搬，一字不动。含项目事实断言的固定句（如"全过程监理""三同时""达标排放"）必须先核实该项目确有证据支撑才可预填，没证据就改替代表述或如实披露。
3. **数据缺就标缺，绝不编造。** 资料里没有的金额、指标、日期，标注「待补充」，不臆造数字。
4. **排版 100% 照模板。** 所有字体、字号、行距、页眉页脚、封面、签章页都在 Word 模板里做死，代码只灌数据不碰样式。

## 目录结构

```
post-eval-report-builder/
├── SKILL.md            技能说明书（Claude 读它决定怎么干活）
├── reference/          各类规范：股权类/工程类的章节骨架、口径话术、格式规范，
│                       以及送审后批注处理、成功度细化评分、专项报告提炼等流程
├── scripts/            处理脚本
│   ├── read_inputs.py    读输入资料（Excel/PDF/扫描件）→ 结构化 data.json
│   ├── ocr_pdf.py        扫描件 PDF 转文字（pdftotext + tesseract 中文 OCR）
│   ├── make_charts.py    出财务图 / 投资控制对比图 / 防伪码占位 → PNG
│   └── build_report.py   docxtpl 渲染：模板 + data.json + 插图 → 成品 docx
├── templates/          Word 模板（带 Jinja 占位符的 .docx）
└── examples/           虚构脱敏示例（供参考，非真实项目数据）
```

## 快速开始

### 安装

作为 Claude Code skill 使用，把整个目录放到技能目录下即可：

```bash
git clone <this-repo> ~/.claude/skills/post-eval-report-builder
```

Claude Code 会自动发现该 skill；当你要求做投后评价报告时它会被触发。

### 依赖

脚本依赖以下 Python 库和系统工具：

```bash
# Python 库
pip install python-docx docxtpl openpyxl xlrd matplotlib qrcode

# 系统工具（macOS 用 brew，Linux 用 apt）
brew install poppler tesseract tesseract-lang   # poppler 提供 pdftotext/pdftoppm；tesseract-lang 含中文包
```

其中 `pdftotext`、`pdftoppm` 来自 poppler，`tesseract` 需装中文语言包（`chi_sim`）用于扫描件 OCR。

### 工作流

1. **识别范式**——股权类还是工程类，决定用哪套规范、模板、话术。
2. **读资料**——`read_inputs.py` 把 Excel 财务数据、文字 PDF、扫描件 PDF（走 OCR）结构化成 `data.json`。
3. **填确定项**——对照 reference 规范，AI 只填能确定的事实（项目名、金额、日期、主体、财务数据、固定话术）。
4. **留判断处**——风险定档、成功度打分、评价结论用醒目占位符留空，附对应话术提示。
5. **渲染 docx**——`build_report.py` 读模板 + data.json + 插图，输出成品 `.docx`。评估师打开补判断、按 F9 更新目录域后定稿。

- 一切专业判断、评分、风险定档、评价结论，须由具备相应资质的评估师复核并定稿，并由其负责。
- 使用者须对最终报告的真实性、合规性负责。
- 工具生成的内容可能存在错误或遗漏，交付或使用前**必须**经人工逐项核验。

请勿将本工具的中间产物直接作为正式评估结论对外出具。
