# 模板制作说明（下一步要做的核心资产）

这个 `templates/` 目录要放**两份 Word 模板**，是整个 skill 保真度的天花板——成品报告
就是这两份模板本身，代码只往里灌数据：

- `股权类模板.docx`  —— 股权投后评价（四章制、宋体正文、中文编号、含 4 段免责声明）
- `工程类模板.docx`  —— 工程投后评价（七章制、仿宋正文、阿拉伯多级编号、无独立声明章节）

`scripts/build_report.py` 里的 `TEMPLATE_PATHS` 已经指向这两个文件名，模板做好放进来即可跑通。

---

## 怎么做（拿真实报告改，别从零画）

1. **拿一份排版最规范的真实报告**当底子（股权类用一份被投企业股权投评报告作范本，工程类用
   一份工程建设投评报告作范本——同属国资体系、骨架最全的那份）。
2. 在 Word 里**把"随项目变的内容"替换成 Jinja 占位符** `{{变量名}}`，**把"固定不变的话术"
   原样留着**（免责声明、七项原则、四制句、三同时句这些一字不改，不要变成变量）。
3. **表格**：把要循环的那一行改成 `{% for 行 in 表数据 %}...{{ 行.列名 }}...{% endfor %}`
   （docxtpl 表格循环写法：`{%tr for ... %}` 放在行首单元格）。
4. **图片**：在要插图的位置放 `{{ 投资控制图 }}` 这样的变量名，`build_report.py` 会用
   InlineImage 把 PNG 塞进去。
5. **需专业判断处**：在模板正文里预留 `{{ 风险综合分析_战略风险 }}`、`{{ 成功度总分 }}`、
   `{{ 评价结论 }}` 这类变量，AI 渲染时填的是「【待评估师判断：…参考话术见…】」占位文案，
   评估师打开后替换。
6. **封面 / 页眉页脚 / 分节 / 目录域**全部在 Word 里做好（红头横幅、页脚防伪二维码横幅、
   宽表横向分节、TOC 域），docxtpl 会原样保留。
7. 存成 `.docx` 放进本目录。

## docxtpl 常用语法速查

| 需求 | 写法 |
|---|---|
| 插变量 | `{{ 变量名 }}` |
| 表格行循环 | 行首单元格写 `{%tr for r in 列表 %}`，行尾单元格写 `{%tr endfor %}`，中间 `{{ r.字段 }}` |
| 条件显示 | `{% if 有退出 %}...{% endif %}`（如处置退出章无内容则整段不出） |
| 插图片 | 模板放 `{{ 图变量 }}`，代码用 `InlineImage(doc, png路径, width=Mm(150))` |
| 富文本(分段设色/加粗) | 代码用 `RichText`，模板放 `{{ rt变量 }}` |
| **段落级列表循环**（对策建议、附件这种不用表格的 list） | **必须三段独立**：①`{%p for item in 对策建议 %}` ②循环体 `{{ item }}` ③`{%p endfor %}`。`{%p ... %}` 会替换掉整个所在段落，若把 `{{ item }}` 和 `{%p for %}` 挤在同一段，内容段会连同 for 一起被吃掉，什么都不输出（曾在报告第8/9章空白栽这）。 |

## 这轮踩的坑（做股权类会再撞，务必先看）

1. **`{%p for%}` 段落循环必须 for/内容/endfor 三段独立**——见上表最后一行。表格循环用 `{%tr%}`（且 for/endfor 分四行放，见下条），段落列表循环用 `{%p%}`（三段），两者别混。
2. **`{%tr%}` 表格循环 for-tag 和 endfor-tag 不能放同一行**：正则每个 `<w:tr>` 只提一个标签，会把 for 吃掉报 `unknown tag 'endfor'`。正确=四行表：表头行 / 只放 `{%tr for%}` 的行 / 内容 `{{row.x}}` 行 / 只放 `{%tr endfor%}` 的行。
3. **别在模板里硬编码给评估师看的提示文本**（如"【待评估师判断：综合得分由评估师核算…】"）。这类提示应该走 context 的字段占位（AI 渲染时填），不要写死在模板 N() 里——写死会原样渲染进每一份成品，且改成品删不掉根，必须回模板源头删（曾在成功度段栽这，删了两遍才净）。判断项的"（供评估师核定）"提示放在 context 字段值里，不放模板。
4. **python-docx 的 add_paragraph/add_table 自动插在末尾 sectPr 之前**，别用 addprevious 挪元素（会破坏 docxtpl 表结构，导致 `{%tr%}` 循环搬运失败）。
5. **格式硬标准模板层就做死，别等评审挑**（曾在首次送审，"首行未缩进/未分页/目录没更新"全被评审当问题挑出来）：
   - **正文首行缩进 2 字符**：所有正文段设首行缩进，用 `w:ind` 的 `firstLineChars="200"`（=2字符，不受字号影响，比 `firstLine=Pt(21)` 稳）。**只排除：各级标题（Heading）、目录段、附件清单项（"1. xxx"）、封面居中标题**。⚠️ **冒号字段行（建设单位：/出资单位：/项目名称：/建设地点：/项目性质：）也要缩进——别自作主张排除它们**（曾在第一版把字段行当"不该缩进"排除掉，评审截图圈的正是这几行"首行未缩进"，返工。评审要的是全文统一缩进，字段行不例外）。
   - **每章章标题段前分页**：第 2 章起每个 Heading 1 章标题设 `page_break_before = True`，全书各章另起一页（第 1 章紧接目录自然翻页可不设）。
   - **目录设"打开时更新域"**：`settings.xml` 加 `<w:updateFields w:val="true"/>`，Word 打开时提示更新目录页码，省得每份都手动 F9。
6. **成品送审后的批注修改，优先在成品 docx 上做外科手术，别重跑模板渲染链**（除非模板本身有 bug）。因为 /tmp 的 context.json 和构建脚本可能已被系统清掉、重建易引入回归；成品改动多是局部（改数/换词/补段/加格式），用 python-docx 按"文本内容定位段落→清空原 run 把新文本写进首 run 保留字体"精改更稳。改完必须解包 document.xml 磁盘验证（别只信子 agent 报告），核对：改动落了、数字锚点没动、段落数增减对得上。

制作后自检：随便灌一组假数据用 `build_report.py` 渲染一次，Word 打开看排版、按 F9 更新目录。**特别检查所有 `{%p for%}` 列表段（对策建议/附件）和 `{%tr%}` 表格有没有真渲染出内容，别只看不报错。**

## 客户评审批注沉淀的通用红线
工程类报告首次送审后，评审挑出的 5 条通用问题（禁"倒逼"、禁 AI 对仗腔+判断段要具体化、主体写全称禁"企业/本公司"、总投资口径按预算并列概算结算、前期决策分步骤+交代可研）已写进 `reference/工程类-口径话术.md` 第十节。**写正文前先过一遍那节**，别等评审再挑。
